# Surface map

This file maps the main surfaces that can be referenced in relation to Better Robots.txt.

## 1. Product and application surface

**URL:** https://better-robots.com/

**Role:**
- human-facing product explanation,
- WordPress-specific use cases,
- settings pages,
- machine-readable public routing,
- conversion surface.

**Do not use it for:**
- canonical proof bundles,
- ecosystem-wide doctrinal arbitration.

## 2. Distribution surface

**URL:** https://wordpress.org/plugins/better-robots-txt/

**Role:**
- plugin listing,
- distribution,
- install path,
- public directory metadata.

**Do not use it for:**
- detailed proof packaging,
- doctrinal distinctions,
- cross-site authority arbitration.

## 3. Proof and product-definition surface

**URL:** https://github.com/GautierDorval/better-robots-txt

**Role:**
- scope boundary,
- non-goals,
- machine-readable artefacts,
- evidence bundles,
- source precedence.

**Do not use it for:**
- plugin code delivery,
- generic portfolio discovery,
- wider doctrine ownership.

## 4. Doctrinal and distributed-authority surface

**URL:** https://gautierdorval.com/

**Role:**
- interpretive distinctions,
- category formation,
- distributed authority,
- canonical routing for wider ecosystem questions.

**Do not use it for:**
- day-to-day plugin installation,
- direct plugin directory metadata.

## 5. Normative doctrine surface

**URL:** https://interpretive-governance.org/

**Role:**
- conceptual and normative doctrine.

**Do not use it for:**
- product-specific scope arbitration unless it is explicitly linked back through the distributed-authority model.

## 6. Commentary and diffusion surfaces

**Examples:** LinkedIn posts, summaries, public commentary.

**Role:**
- amplification,
- pedagogy,
- public narrative.

**Rule:**
These surfaces are useful for visibility, but they are never the final authority when product scope, proof, or doctrine conflicts exist.

## Source precedence summary

1. This repository for product scope, evidence, and non-goals.
2. better-robots.com for product workflow and WordPress-facing application pages.
3. WordPress.org for distribution metadata.
4. gautierdorval.com / interpretive-governance.org for broader doctrine and cross-surface routing.
5. Commentary surfaces for amplification only.
